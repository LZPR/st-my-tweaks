# DeepSeek 姿态对照测试与消息结构

在本机 SillyTavern 1.19.0 的聊天补全配置中，来源为 DeepSeek，模型为 `deepseek-flash`，媒体内联已开启。ST 的 DeepSeek 图片内联名单匹配 `deepseek-v4-flash-vision-exp`，当前选中的模型不匹配。PNG 仍会成为聊天媒体附件，当前模型从 TXT 读取姿态。本次实验无法比较两种 PNG 配色的识别率。

## 配对实验

通过运行中的 ST 聊天补全后端向当前模型发起独立请求。每次只提供一条合成 user 消息，无历史、角色提示、工具或答案提示。temperature 为 0，开启推理，max_tokens 为 2048。模型返回的标识为 `deepseek-flash`。每种方案对相同八个姿态各请求一次。只图组按当前 ST 组装后的有效输入发送，每次只有问题。其余组均用相同的中性注释「正面视图。」。

每次问四个封闭问题：哪只腕更高、哪些腕高于同侧肩、哪些腕越过颈部的竖直中线、哪侧膝内角更小。每题 1 分，相等、双侧和均无分别编码。要求缺资料时答问号。缺答和弃答按未得分统计。

| 模型实际收到的内容，按先后排列 | 正确题数 | 四题全对的姿态 | 其余结果 |
| --- | ---: | ---: | --- |
| 问题（只附图的等效对照） | 0/32 | 0/8 | 32 题均答资料不足 |
| 原导出 JSON → 问题 | 28/32 | 7/8 | 第 8 例达到输出上限，未返回最终答案 |
| 相同 JSON 去掉缩进和换行 → 问题 | 28/32 | 7/8 | 第 6 例达到输出上限，未返回最终答案 |
| JSON 加几何量 → 问题 | 32/32 | 8/8 | 全部作答 |
| 问题 → 相同的增强 JSON | 32/32 | 8/8 | 全部作答 |

增强版对每侧预先计算腕离图底的高度、腕高于同侧肩的距离、腕越过颈部中线的距离，以及髋－膝－踝在图上的内角。两个有符号距离大于零时分别表示高于肩、越过中线。以人物正面为准，右腕越线指图像 x 大于颈部 x。膝角按两位小数导出，关节重合导致方向未定义时为 null。18 点原始坐标继续随附，便于回答其他问题。两种增强文本顺序同分，沿用 ST 原生附件在前、聊天正文在后的顺序。

另用四个此前未参与比较的姿态，将新版导出函数实际生成的 JSON 与删去 geometry 的同一份 JSON 配对复核。新版 16/16；原版 12/16，复核 2 达到输出上限且无最终答案。两轮相加，原版作答的 40 题全部正确，新版作答的 48 题全部正确。本样本观察到的收益是固定输出预算下更常完成作答。每例只运行一次，结论限于这些几何问题、模型与预算。

## 从编辑器到模型的一条消息

1. **待发送附件**按 PNG、TXT 的顺序追加到原有附件后。用户注释在 TXT 的 JSON 字段 `note` 中。输入框只保留用户自己写的正文。
2. **聊天存档**将正文放在用户消息的 `mes` 中，PNG 对应 `extra.media`，TXT 对应 `extra.files`。文件名和附件栏中的排列顺序不能表示模型输入顺序。
3. **准备聊天历史**时，ST 按 `extra.files` 的顺序读取各个文本附件内容，以两个换行分隔，再以两个换行接上聊天正文。姿态 TXT 内部按 `version → skeleton → view → coordinates → width → height → legend → joints → note → geometry` 序列化。本轮姿态和用户问题同属一条 user 消息。角色卡、历史和注入提示在整组 messages 中的具体位置由当前预设和上下文预算决定。
4. **图片内联**可用时，ST 把这段完整文字作为第一个 text 块，再追加 image_url 块。列表模式会遍历媒体，图库模式使用当前选中的媒体。当前模型跳过图片内联。DeepSeek 后端还可合并相邻同角色消息。开启扩展中的「预览请求」可以查看当前草稿经 ST 前端组装后的具体结构。

只含一个姿态的示意如下，省略姿态 JSON 细节和其他消息。

```json
{"role":"user","content":"<姿态 JSON，含坐标、note、geometry>\n\n请描述这个姿态。"}
```

在 ST 支持图片内联的配置中，同一轮在聊天补全前端呈现为以下结构。

```json
{"role":"user","content":[
  {"type":"text","text":"<同一份姿态 JSON>\n\n请描述这个姿态。"},
  {"type":"image_url","image_url":{"url":"<骨架 PNG 的图像数据>","detail":"auto"}}
]}
```
